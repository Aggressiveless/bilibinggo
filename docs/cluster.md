
# Binggo 工作集群

每台机器登录自己的 B 站账号后，可以参与关键词检索并同步活动。使用支持两阶段协作的版本，并完成本机模型设置及连接测试后，该节点也可以领取视频检测任务。

1. 在主机打开 **工作集群**，填写主服务器的 HTTPS 地址和本机节点名，点击 **发起工作集群**。
2. 点击 **显示邀请码**，把同一 HTTPS 地址和邀请码交给计划加入的节点管理员。
3. 其它机器在自己的 Binggo 页面选择 **参与工作集群**，输入本机节点名、地址和邀请码。主机也会领取任务。节点重启后自动恢复同步。
4. 页首显示本机节点名称、角色和同步状态。点击「改名」即可修改自己的节点名称。「集群管理」提供地址、邀请码和退出入口。主节点可在页首暂停或恢复主动搜集。解散后成员需要退出旧集群并重新加入。

## 主服务器入口

中心与本地仪表盘使用同一个 Binggo 进程。中心数据库位于主服务器的 BINGGO_HOME/data/cluster/cluster.db，普通成员通过 HTTPS 调用 v1 协议，不访问数据库。中心初期可使用单机 SQLite，不需要增加数据库服务。将集群目录与普通账号数据一起纳入异机备份，恢复时保持中心的集群标识和同步游标。SQLite 在线快照适合运行期间的备份。

如果主机的 Nginx 已对仪表盘启用 HTTP Basic Auth，在已配置好证书的 HTTPS server 中单独添加以下位置。集群接口使用邀请码或各节点自己的 Bearer 凭据，仪表盘其它路径沿用原有认证。将端口改成本机 Binggo 监听端口。

    location ^~ /api/cluster/peer/v1/ {
        auth_basic off;
        client_max_body_size 256k;
        proxy_set_header Host 127.0.0.1:8182;
        proxy_set_header Authorization $http_authorization;
        proxy_pass http://127.0.0.1:8182;
    }

邀约与管理面板应只交给有权操作的用户。邀约码用于加入，已加入节点继续使用各自独立的凭据。主机可按可信内网或节点 IP 配置入口访问范围。HTTP 仅用于本机回环测试。

## 调度与活动同步

每轮使用一个关键词，按「抽奖」「福利」「奖品」「转发抽奖」「抽奖活动」「粉丝福利」循环。主节点按节点加入顺序轮流分配整轮检索，跳过离线或暂时无法领取任务的节点。被选中的节点按发布时间从新到旧逐页检索，最多 60 页，收录目标为 1,000 个去重后且未检测过的视频。若检索节点离线，下一个可用节点从待领取的页接续。各节点分批同步本机 BV 收录表，主节点将其与集群完成检测的 BV 取并集并持久保存。只传输 BV 标识。上线节点上传历史期间暂停派发新任务，已领取的任务可以完成。历史 BV 会从待检测队列中移除，也会在后续搜索中跳过。新调度规则从升级后的下一轮开始生效。

主节点在「节点分工」里给每台节点勾选「追踪 UP 主」「主动搜集」，可以同时勾选两项。主动搜集包括关键词检索和视频检测。关键词在勾选的节点中轮换；暂停主动搜集后，已领取的工作可以完成，待检索和待检测任务留在队列，追踪继续运行。离线节点恢复连接并就绪后可以领取任务。

收录达到 1,000 个视频后，主节点停止派发新搜索页，等已领搜索任务返回后开始分配视频检测。若可用结果页已搜完，主节点检测已有视频。每个节点同时执行一项，全组按设置的并行上限派发。平台限流时暂停领取新任务至冷却结束。每轮检测结束后，在线且已同步 BV 的节点依次导入集群活动目录。在「集群管理」开启本机轮间参与后，轮到该节点时，Binggo 会在导入后用当前授权账号对本机全部可参与活动执行一次「自动顺序参与」，任务结束才移交下一台。授权按当前集群和账号保存。离线或超时的节点恢复连接后继续同步活动。最后一台处理完后开始下一轮。

检索页数按成功完成的搜索页任务计算。升级前已经清理的轮次无法补计，页面会显示累计统计起始轮次。

视频转化率按“核验到至少一项开放活动的视频数 ÷ 有统计记录且已完成检测的视频数”计算。工作集群页显示全组本轮转化率及各节点累计命中率，主动检索页显示本机本轮转化率。累计统计能补计升级时仍保留的检测记录。「数据源 → 主动检索 → 成果展示」的「集群检出活动」按截止时间列出仍开放的动态，同一动态只计一次。团队成员上传的已有活动继续同步。

节点批量上传仍开放的活动。开奖时间未知或只有推算值时，活动页显示「待确认」，共享记录携带空值。旧版成员继续收到有明确开奖时间的活动，升级后会按游标补齐待确认的活动。主机按动态 ID 汇总活动，向各节点同步新增、更新和已核验的关闭状态。Cookie、参与记录和 API Key 均不随协议传输。

检索任务返回视频 BV。视频检测在同一个任务内检查视频及关联动态、专栏、短链和发布者线索，确认的活动由主节点自动同步。节点会定期续租，失联超时后任务可由其它节点领取。未确认提交的结果在恢复连接后补交。正文分析结果按完整输入、提示词和模型配置共用 30 天缓存。

## 集群追踪 UP 主

「工作集群 → 追踪 UP 主」按 UID 合并各节点的监控名单和 UP 合集作者，显示名单来源和最近的检查结果。支持整批追踪的节点会周期性同步名单与工作状态。

主节点为节点勾选「追踪 UP 主」、保存分工后，点击「开始追踪」。已在追踪时，保存分工会把后续工作交给新勾选的节点。追踪会读取最近 24 小时的空间动态，核验本人抽奖及转发的原活动。新版节点按已有规则从视频、专栏或 Opus 合集提取链接，模型已就绪的追踪节点可以并行核验这些链接。支持动态检查的旧节点也可以参与核验。核实的活动随检查进度同步到集群目录。

## 集群工作日志

「日志」页显示任务队列和集群工作日志。集群工作日志默认显示本机集群任务和全组调度事件，可切换到全部节点或仅看异常。

主节点保存最近 2,000 条事件，界面同步其中最新 80 条。日志记录领取、完成、重新派发、限流和活动同步，使用固定错误原因，不记录账号凭据、模型密钥和请求原文。已存在的集群从升级后开始记录。

「数据源 → 主动检索」显示本机领取的集群任务、本轮贡献及近期结果。页数、去重后收录的视频和核验结果只计本节点完成的集群任务。独立检索仍使用原来的统计。正在运行的集群从升级后开始统计本轮新增贡献。
